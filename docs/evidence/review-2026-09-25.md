## Checked and found fine

- **Export** reads only the person's own `memory_index` rows. Recovered text is
  kept only for blob ids in those rows, so a teammate's memory that comes back
  from the team scope is dropped. Nothing is cached; `Cache-Control: no-store`;
  the file name is built from a date. Rate limited per person and per address.
- **Team routes** require current membership, never name a teammate, and rate
  limit invite and leave. Cross-site requests cannot act: cookies are
  `SameSite=Lax`, the header identity needs script access, and CORS is an
  allowlist.
- **Hide/unhide** acts only on the person's own rows (`ownMemoryOf`), needs six
  characters of the blob, matches an exact prefix rather than `LIKE` (blob ids
  contain `_`), and refuses an ambiguous prefix. Hidden memories are filtered
  from recall and from dedupe, and kept in the export.
- **A team fact cannot pose as a correction.** `/team remember "[correction] …"`
  is stored as a decision: the leading tag is stripped before the line is
  built. Tested in `format.test.ts`, because the corrections pull trusts the
  parsed type and would otherwise put it first for every member.
- **Web command streaming** returns the CLI's JSON (with `/export`'s files) only
  on `x-hippo-channel: cli`, and those files are the requester's own.
- **Evidence** leaves team namespaces out of every per-person number.
  `TEAM_PREFIX` has no `LIKE` wildcards in it.
- **`plan-push`** prints the database host, never the URL, and refuses anything
  that is not an added column, table or index, or that reports data loss.
- **Recall changes** keep selection by distance; only order and the number of
  queries changed, and `pnpm demo` passed after each.

## Accepted as they are

- `GET /api/me/memories`, `/team` and `/account` are limited per address but not
  per person. They are reads, and the per-address ceiling bounds them.
- A guest id is a bearer secret: whoever holds the UUID is that guest. That is
  the design of guest mode, and the ids are random v4 UUIDs.
