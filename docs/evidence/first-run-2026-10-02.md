# A first visit, followed in a browser — 2026-10-02

Local stack (`bun run dev`, Postgres on 5433), `google/gemini-2.5-flash`, the
mainnet relayer, a fresh isolated browser context, so a new guest with no
chats. The viewport was under 768px, which is the phone layout. This followed
the README's "See it work in three clicks" as rewritten in `fe26797`.

## What it found, and what was fixed

| Seen | Fix |
|---|---|
| On first load the Memory sheet opened by itself and covered the whole chat. The rule was "open unless the person closed it", which is right beside the chat on a desktop and wrong as a modal on a phone. | `5398c0a`: on a phone the sheet opens only when asked. A desktop choice is untouched. |
| Both memories reached `stored` at 19:01:06Z (local `memory_index`, blob ids present), yet the line under the box still read "Nothing on Walrus yet · no memory yet" 90 s later. `useMe` loaded once; the README step that says to wait for that line could never complete. | `3a48c16`: the line reloads when a turn ends and when a write lands. |
| After "New chat" in the phone sidebar, the sidebar stayed open over the new chat. | `5398c0a`: it closes after New chat, a chat, or a link. |
