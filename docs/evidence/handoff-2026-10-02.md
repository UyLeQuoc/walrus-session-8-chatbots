## 1. Approve and apply the production schema

```bash
bun run --filter @hippo/db plan-push ../../.env.production           # read the plan
bun run --filter @hippo/db plan-push ../../.env.production --apply   # only if it says "purely additive"
bun run --filter @hippo/db plan-push ../../.env.production           # should now say 0 statements
```

Expected plan: 9 statements, `data loss: false`. Two `CREATE TABLE`
(`conversations`, `messages`), two `ADD CONSTRAINT … FOREIGN KEY` on those new
tables, two `CREATE INDEX` and three `CREATE UNIQUE INDEX` on them. Nothing
touches an existing table. If it shows anything else, stop: production has
drifted from `packages/db/src/schema.ts` at `0343083^`.

Rehearsed on a local database built from that older schema: 9 statements,
"purely additive", applied, re-plan 0. Before `ee8b54b`, `--apply` would have
refused this plan, because the foreign keys and unique indexes failed the
additive check; they now pass only on tables the same plan creates.
